# Exceed Box Audit

## Verdict

**Not shippable to the Japan office.** The real app and backend do not share a working contract: successful Leads, Lead detail, Pipeline, Dashboard, and Team responses have shapes or stage values the app cannot consume, multiple visible actions send bodies the backend rejects, and server-side task isolation has holes. The passing backend suites do not cover this integration boundary.

## Findings

### Critical

- `exceed-box-ios/src/auth/AuthContext.tsx:106`, `exceed-box-ios/src/auth/AuthContext.tsx:115` — both real sign-in paths are stubs: email/password always throws “not connected,” and Google always throws “not connected.” Only mock mode can authenticate, so no Japan-office user can enter the real app. Wire Supabase email/password and OAuth, persist the real session/JWT, and exercise both flows in a non-mock build.
- `exceed-box-ios/src/api/client.ts:35`, `exceed-box-ios/eas.json:15` — the only in-repo real API fallback is `http://127.0.0.1:8912`, and production/preview build profiles provide no API URL. An installed iPhone/iPad therefore calls itself unless undeclared remote build configuration happens to override it. Require an HTTPS API URL per non-mock build and fail the build when absent.
- `exceed-box-ios/src/api/client.ts:137`, `exceed-box-app/app/tasks.py:111` — app expects `Task{id,lead_name,lead_score,escalation_level}` → backend returns `{task_id,lead,score,escalation,...}`; seeded task types also include values absent from the app. Cards receive undefined IDs/labels, actions address `/api/tasks/undefined`, and some task types crash. Emit the canonical `Task` schema and contract-test every seeded type.
- `exceed-box-ios/src/api/types.ts:113`, `exceed-box-app/app/api.py:226` — app expects `LeadSummary{region,source,owner_name,exit_state,...}` → backend omits/renames those fields. `LeadListItem.tsx:24` reads `lead.region.length`, so a successful Leads request crashes. Return canonical rows (with server-side contact redaction) and render-test the real payload.
- `exceed-box-ios/src/api/client.ts:172`, `exceed-box-app/app/api.py:259` — app expects flat `LeadDetail` → backend returns `{lead,identities,regions,score,...}`. Opening any lead reads missing `stage`, `region`, and `score_breakdown` fields and crashes. Fix one canonical schema and render-test a real `/api/leads/{id}` response.
- `exceed-box-ios/src/api/client.ts:217`, `exceed-box-app/app/api.py:472` — app expects `{buckets:[{label,label_ja,...}]}` → backend returns `{stages:[...]}` without labels. `PipelineScreen.tsx:55` calls `data.buckets.reduce`, so a successful request crashes. Fix the envelope/fields and contract-test it.
- `exceed-box-ios/src/api/types.ts:280`, `exceed-box-app/app/api.py:525` — app expects `{tiles,trend,trend_flag,hot_leads,by_rep,...}` → backend returns `{kpis,flags,...}` and count rows shaped as `{n}`. `DashboardScreen.tsx:62` calls `data.tiles.map`, so a successful request crashes. Match or explicitly map the declared contract, then test populated and empty responses.
- `exceed-box-ios/src/api/types.ts:309`, `exceed-box-app/app/api.py:676` — app expects `{members:[...]}` → backend returns `{data,page,page_size,total,digest}`. `TeamScreen.tsx:32` stores `undefined` and then reads `members.length`; Team, Member Tasks, and owner picker fail. Consume the paginated envelope and map canonical members.
- `exceed-box-ios/src/api/client.ts:187`, `exceed-box-app/app/api.py:361`, `exceed-box-app/app/api.py:391`, `exceed-box-app/app/api.py:419` — app expects `LeadDetail` from assign/stage/signal → backend returns a raw lead row or minimal mutation receipt. Lead detail stores that receipt as the whole view model, shows success, then crashes on missing detail fields. Return/refetch canonical detail before success and preserve modal state on failure.
- `exceed-box-ios/src/api/types.ts:74`, `exceed-box-app/app/api.py:172` — contract/app stages are `engaged`, `meeting_booked`, `in_negotiation`; backend accepts and emits `responded`, `booked`, `negotiating`, and stores exit states in `stage` while the app expects separate `exit_state`. Lead badges cannot map these values, and moving to three contract stages returns 422. Migrate backend constants/data/queries to the SPEC model and test every forward/exit state end to end.
- `exceed-box-ios/src/screens/TodayScreen.tsx:45`, `exceed-box-app/app/api.py:652` — Snooze sends `{action:'snooze', until}` while the backend only accepts `{action:'reschedule', due_at}`. Every Snooze tap gets 422; the catch at `TodayScreen.tsx:47` suppresses it, so the button appears dead. Align the request contract and show the returned error with retry.
- `exceed-box-ios/src/screens/MemberTasksScreen.tsx:84`, `exceed-box-app/app/api.py:637` — Reassign sends `owner_user_id`; backend requires `owner`. Every task reassignment gets 422, and the screen provides no error state for the failed action. Align the field name and surface the error without closing/losing picker state.
- `exceed-box-app/app/api.py:269` — lead detail returns every task on the lead without filtering by task owner. Reproduced: a sales owner received another rep's task; marketing can likewise bypass the `/api/team` 403 by reading tasks embedded in any lead. Filter tasks in SQL by caller/task ownership unless `tasks.all`, and add cross-owner tests for sales and marketing.
- `exceed-box-app/app/api.py:589` — task creation checks that the lead exists but not that the caller may view it. Reproduced: sales created a task on sales2's lead (`200`) and then received that foreign lead through `/api/today`. Require lead access in the write and add a sales-vs-sales2 denial test.

### High

- `exceed-box-ios/src/screens/LeadsScreen.tsx:73`, `exceed-box-app/app/api.py:192` — search promises “name, email, company,” but real SQL searches only name and company. Searching an email returns an empty result even when that contact exists. Search identities safely in SQL with the same role/redaction rules, or remove “email” from the control.
- `exceed-box-ios/src/screens/AdminUsersScreen.tsx:178`, `exceed-box-app/app/api.py:701` — “Send invite” only inserts an `app_user` row; it never creates or invites a Supabase Auth user or sends an invitation. The UI reports a completed invitation for an action that did not happen. Implement the real invite flow, or rename/remove the control and accurately describe pre-approval only.
- `exceed-box-ios/src/components/LeadDetailContent.tsx:348`, `exceed-box-app/app/api.py:174` — Edit details submits `email` and `phone`, but the backend silently drops both because they are not editable fields. The app can say Save succeeded while contact changes did not happen. Support identity edits with audit/dedupe semantics, or remove those inputs; never silently discard submitted fields.
- `exceed-box-ios/src/screens/PipelineScreen.tsx:67` — Move stage catches every failure without rendering an error. A 403, 422, or network outage leaves the picker open with no explanation, contrary to the required visible handling of role-gated/destructive failures. Store and display `describeApiError(e)` and provide a working retry.
- `exceed-box-ios/src/screens/TodayScreen.tsx:33` — Complete suppresses every failure. The card remains, but the user gets no indication whether the tap registered or why it failed. Show an action-level error and retry; do not use an empty catch as the only rollback.
- `exceed-box-ios/src/api/types.ts:55`, `exceed-box-app/app/api.py:578` — app expects task create `{type,owner_user_id,lead_id,due_at,reason} → backend reads `{type,owner,lead_id,due,reason}` and returns only `{id}` instead of `Task`; backend also allows the contract-required due date to be omitted. The client method cannot satisfy the route even if a create-task control is added. Adopt one body/response schema and validate every required field.
- `exceed-box-ios/src/api/types.ts:194`, `exceed-box-app/app/api.py:295` — app expects lead create `{name,source,region,purpose,...} → backend requires `channel`, ignores region/purpose, and returns an upsert marker instead of `LeadDetail`; calling the typed client produces a 500 KeyError for missing `channel`. Align validation and response shape, returning a structured 422 for invalid bodies.
- `exceed-box-ios/src/api/types.ts:169`, `exceed-box-app/app/scoring.py:107` — app expects score explanation `breakdown`/`decay_note` → backend returns `components`/`summary`/`hot`. The declared score endpoint cannot be rendered by the client. Canonicalize the response and add a contract test.
- `exceed-box-ios/src/screens/AdminUsersScreen.tsx:31`, `exceed-box-ios/src/screens/TeamScreen.tsx:31`, `exceed-box-app/app/api.py:468` — Admin hard-stops at 100 users, Team never requests subsequent pages, and Pipeline hard-stops each stage at 200 cards. These are list endpoints/screens without working pagination, contrary to the Definition of done. Implement cursor/page loading and expose accurate totals/has-more state.
- `exceed-box-ios/src/screens/TodayScreen.tsx:66`, `exceed-box-ios/src/screens/LeadsScreen.tsx:86`, `exceed-box-ios/src/screens/TeamScreen.tsx:53`, `exceed-box-ios/src/screens/AdminUsersScreen.tsx:95` — each empty branch removes the `FlatList`/`ScrollView` that owns `RefreshControl`; users cannot pull to refresh an empty list. Keep the refreshable list mounted and render the human empty state as its empty component. Pipeline and Member Tasks have the same defect.
- `exceed-box-ios/src/screens/DashboardScreen.tsx:56` — Dashboard has loading, error, and populated branches but no screen-level empty branch. A valid all-zero/empty response renders a grid of empty sections, failing the required fourth state. Define an explicit meaningful empty condition and keep retry/refresh available.
- `exceed-box-ios/src/screens/MemberTasksScreen.tsx:58` — Complete, Snooze, and Reassign have no `catch`; a rejected request becomes an unhandled promise rejection with no user-facing error or retry. Preserve the list/picker and render the API error at action level.
- `exceed-box-app/tests/test_permissions.py:130` — “see own tasks” asserts only 200 plus envelope keys, with no task fixture or ownership assertion; `test_matrix_see_everyones_tasks` at line 140 checks only `/api/team` status. Both pass while the reproduced `/api/leads/{id}` and task-create leaks remain. Add cross-owner tasks and assert contents across every response path.
- `exceed-box-ios/src/auth/AuthContext.tsx:86`, `exceed-box-ios/App.tsx:7` — mock mode accepts any password and serves/mutates fixture data, but the signed-in UI has no persistent “demo/mock data” indicator. With the supplied `.env.example`, invented leads, tasks, KPIs, and apparent successful writes are presented as real. Add an unmistakable environment banner and prevent mock-enabled release builds.

### Medium

- `exceed-box-ios/src/api/mocks.ts:832` — mock “First sends” is the invented formula `totalLeads * 7 - 41`, and the 14-day trend at lines 834–843 is synthetic modular arithmetic; Dashboard renders both as authoritative metrics. Remove invented metrics or label the entire mock surface as demo data.
- `exceed-box-ios/src/screens/DashboardScreen.tsx:50`, `exceed-box-ios/src/components/ScreenContainer.tsx:26` — Dashboard opts out of the 560-point iPad cap and its content has no replacement max width, so tiles/sections expand across the full display. Apply a capped dashboard grid/content wrapper while retaining responsive columns.
- `exceed-box-ios/src/screens/LeadDetailContent.tsx:70` — Assign owner suppresses Team-load errors by replacing the roster with `[]`, then opens an unexplained empty picker. Keep the prior roster or show a retryable picker error; do not translate a failed request into “no options.”
- `exceed-box-app/tests/test_permissions.py:314` — the test named “import CSV/create campaigns” only posts one lead; it never imports a CSV or creates a campaign, and the app has no import/campaign screen or client call. Implement the contracted capability and test its real denied/allowed operations, or remove the unsupported claim from the matrix.
- `exceed-box-ios/src/components/TaskCard.tsx:62`, `exceed-box-ios/src/components/FilterChips.tsx:33`, `exceed-box-ios/src/navigation/TabNavigator.tsx:120` — visible action, filter, and tab labels are English-only; Admin and picker controls have the same pattern. This directly breaks “every label needs its 日本語” for the Japan office. Give every user-facing label a small Japanese counterpart, including error/empty/action text.

## Verified working

- `python3 tests/test_decisions.py`: 28/28 passed.
- `python3 tests/test_permissions.py`: 23/23 passed, including unauthenticated/inactive rejection, role denials for Dashboard/Team/Users/import/lead writes, sales SQL filtering on Leads, marketing contact redaction on list/detail, pagination slicing, and signal actor audit.
- Seeded authenticated TestClient smoke: `/api/me`, `/api/today`, `/api/leads`, `/api/leads/{id}`, `/api/pipeline`, `/api/dashboard`, `/api/team`, and `/api/users` all returned 200; their actual keys were captured and compared with the app types.
- Adversarial temporary-DB probes reproduced both task-isolation failures; no production/local data was used.
- `tsc --noEmit`: passed.
- All `onPress`/`onValueChange` sites in `src/screens` and `src/components` were enumerated; no literal empty body, TODO, “coming soon,” `Alert.alert`, or console-only handler was found. The dead/misleading controls are the integration and suppressed-error paths listed above.
